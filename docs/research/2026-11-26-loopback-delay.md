## RTT 與已知真值

對每個 `HEAD /`，伺服器在產生 `Date` **之前**抽一次均勻亂數並等待，隨後讀取系統時鐘，捨去小數秒，每筆重新產生標頭。延遲的方向固定，模擬請求到達與取時之間有抖動。0–5 ms 組只讓實測 RTT ≤5 ms 的請求參與估計，超過門檻就在同一相位重試，20 秒的計時繼續。0–15 ms 組依指定範圍注入延遲，保留所有回應，以觀察較大抖動對算法的影響。

|---:|---:|---:|---:|---:|---:|---:|
| 0 | 0.00–0.00 | 0.00 | 78/78 | 0.824 | 1.487 | 1.487 |
| 5 | 0.02–4.97 | 7.80 | 65/107 | 2.519 | 4.982 | 9.924 |
| 15 | 0.07–14.91 | 18.57 | 90/90 | 8.868 | 19.857 | 19.857 |

## 複核與重跑

共收到 275 筆回應。逐筆核對伺服器實際取時落在本機送出與收到之間，且該時刻向下取整等於 HTTP `Date`。每次估計都從採用樣本重算：下界取 `Date − 收到時間` 的最大值，上界取 `Date + 1 秒 − 送出時間` 的最小值。伺服器記錄的取時時刻只供事後核對。各輪從建立 HTTP 連線前開始計時，第一次達到 ±10 ms 後繼續取樣，直到全寬 ≤10 ms 或時間用完。

在 macOS 或 Linux 的專案根目錄執行以下指令即可各重跑九次量測。不同條件使用相同的起跑相位，隨機序列使用固定種子方便重現。排程與 RTT 仍會隨環境變動。[本機測試程式](../../experiments/http_date/loopback.py)

```sh
python3 experiments/http_date/loopback.py 0
python3 experiments/http_date/loopback.py 5
python3 experiments/http_date/loopback.py 15
```
