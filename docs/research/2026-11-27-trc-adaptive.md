# 由粗掃平均 RTT/2 選細掃步長：本機對照與臺鐵五輪實測

每輪上限 20 秒，從整秒 Date 開始，以 100 ms 相位步長粗掃。找到跨秒位置並取得至少三筆有效樣本後，以粗掃期間的平均 RTT/2 選出後續格距。每輪回報的半寬由實際樣本區間的交集決定。[門檻與邊界決策](../decision/0002-adaptive-http-date-step.md)

## 本機零時差對照

這五輪的區間全寬由單筆的約一秒縮至 80–138 ms，各輪都與零時差相容。結論是多個取樣相位能縮小整秒量化造成的不確定範圍。25 ms 是此次採用的探測格距；站台沒有獨立時鐘真值可核對，資料支持的精度應讀取該輪半寬。五輪全落在相同的 RTT 分級，因此其他分級的選擇由下列本機對照驗證。

伺服器與用戶端共用系統時鐘，伺服器在產生 Date 前後各插入表列額外時間的一半。四組各跑一輪，時差區間都包含真值 0 ms。另以輸入值直接檢查門檻的等號，20、50、100 ms 依序選為 20 ms、25 ms、僅粗掃。

## 重跑五輪

在 macOS 或 Linux 的專案根目錄執行，可取得每輪的粗掃平均、所選步長、整輪平均與上下界。單輪預設起始相位為 173 ms。

```sh
python3 experiments/http_date/adaptive.py https://www.trc.com.tw/tra-tip-web/tip/tip001/tip123/query --phases 173 473 773 373 673 --samples /tmp/trc-adaptive-samples.csv
```
