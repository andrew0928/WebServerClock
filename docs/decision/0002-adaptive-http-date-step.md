# 0002　依粗掃期間的平均 RTT/2 選擇細掃步長

日期：2026-11-27

後續決策：[0003 校正工作階段](0003-calibration-session.md) 將分級依據改為每次工作階段起始的五筆 RTT。以下記錄第一版實驗。

適用範圍：HTTP Date 校正演算法，每輪上限 20 秒。

## 決策

第一筆 `HEAD` 取得整秒 `Date`；接著以 1.100 秒週期取樣，讓每一筆在秒內的位置前進 100 ms。觀察到跨秒邊界且累積至少三筆有效粗掃樣本後，以包含第一筆在內的**全部有效粗掃樣本**計算算術平均 RTT/2，只在此刻選一次細掃步長。

| 粗掃平均 RTT/2 | 接下來的取樣 |
|---:|---|
| 小於 20 ms | 在粗掃區間內每格 10 ms |
| 20 ms 以上、未滿 50 ms | 每格 20 ms |
| 50 ms 以上、未滿 100 ms | 每格 25 ms |
| 100 ms 以上 | 本次實驗保留粗掃區間並結束該輪 |

最少三筆是「已測過幾次」的實驗設定。100 ms 以上的處理是本次對未指定範圍採用的預設。最近幾筆 RTT 的中位數只用來預估何時發出請求；細掃期間即使 RTT 改變，本輪已選的格距仍固定。

## 判讀

步長決定在跳秒區間內探測哪些位置。可回報的時差範圍由各筆實際送出、收到與標頭時間共同決定；回報其中點與半寬。若至時限仍未能確認邊界，回報已有粗掃區間；若樣本交集為空，標示樣本不一致。[實驗 CLI](../../experiments/http_date/adaptive.py) · [本機與臺鐵實測](../research/2026-11-27-trc-adaptive.md)

## 實作順序

區間交集、粗掃轉細掃的條件、下一筆相位與停止條件由 Rust 校正模組持有。單元測試注入指定的收發時間與整秒 Date；`clock-ping URL --calibrate` 負責發送 HTTP 請求、執行 20 秒計時並呈現模組結果。[校正模組](../../src/calibration.rs) · [確定性單元測試](../../src/calibration/tests.rs)
