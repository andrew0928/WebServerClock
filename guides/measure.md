# 量測網站時鐘

```sh
clock-ping https://example.com/path
clock-ping https://example.com/path -t
clock-ping https://example.com/path --monitor
```

三種模式都先以 1 秒間隔對指定路徑送出五次 HEAD，再根據準備階段的 RTT 逐輪校正。每輪最多 20 秒。CLI 跟隨重新導向，使用最終回應的整秒 `Date`。

## 逐行模式

預設執行四輪，每完成一輪向 stdout 輸出一行。可用 `--count 2` 指定輪數，或加 `-t` 持續到 Ctrl+C。第一行顯示初始化完成的本機時間、準備階段成功回應的平均 RTT/2，以及本次校正的步長。若要指定細掃步長，可加上 `--min-step-ms 25`（允許 1–100 ms）。

```text
- [14:20:05] 初始化，RTT/2: 62.5ms，位移: 100ms | 25ms
- [14:20:18] 檢測中，count = 1，100ms - OK，25ms - OK，時間差: -64.3 ms，RTT/2: 100.0ms
```

在終端機上，同一行會從 `100ms - ...` 更新為 `100ms - OK，25ms - ...`（以 25 ms 細掃為例），完成後才補上時間差與 RTT/2。重新導向輸出時，每輪寫入一行完整結果。

檢測列使用該輪完成的本機時間與該輪成功 HEAD 回應的平均 RTT/2。範例中的 100 ms 粗掃與 25 ms 細掃都確認了跨秒。顯示值是邊界兩側「網站時間減本機請求中點」之中絕對值較小的那筆，保留正負號。只做粗掃時僅列出 100ms。細掃已開始但未確認邊界時標示「未確認」，並採用仍有效的粗掃結果。若粗掃未找到邊界，規劃中的細掃會標示「未執行」。該輪沒有有效時差時，顯示「時間差: 未取得」並繼續。

當網站實際快 600 ms，跨秒的兩筆可能接近 −400 ms 和 +600 ms，這個選值規則會得到接近 −400 ms 的結果。步長表示確認跨秒時的取樣格距，真實時差的誤差仍可能接近一秒。若由 CDN 或代理產生標頭，結果反映該設備的時鐘。

## 監控模式

`-m` 或 `--monitor` 在第一筆有效校正結果到手時開啟完整畫面。畫面每 10 ms 以本機目前時間加上最新有效時差更新遠端時鐘，使用本機時區顯示。下一輪校正與時鐘更新同時進行，新結果立即取代舊時差。校正失敗時保留上次成功值及其更新時間，並顯示失敗輪次。若第一輪失敗，會繼續等候第一筆有效結果。

「最新時差」和同列的 RTT/2 來自最近一次成功校正。「檢測中」列出當輪的步長進度，每收到一次成功的 HEAD 回應就更新當輪平均 RTT/2。新一輪開始時 RTT/2 顯示 `—`，直到收到第一筆回應。

```text
最新時差: -26.2 ms, RTT/2: 100ms
檢測中:   count = 3, 100ms - OK, 25ms - 檢測中, RTT/2: 92.5ms
```

畫面也會對輸入網址送一次 GET 讀取 HTML 頁面標題。按 Ctrl+C 會還原終端機並結束。準備失敗或有限輪數中有任一輪未取得結果時，結束碼為 1；全部成功或按 Ctrl+C 為 0，參數錯誤為 2。
