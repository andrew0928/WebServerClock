# 量測網站時鐘

以要量測的 HTTP 或 HTTPS 網址取代範例網址。第一條命令每秒取樣一次，四次後結束。第二條持續逐行列印。第三條在終端機開啟固定畫面。兩種持續模式都能按 Ctrl+C 結束。

```sh
clock-ping https://example.com
clock-ping https://example.com -t
clock-ping https://example.com --monitor
```

每次取樣都向指定主機和連接埠發送 `HEAD /`，並跟隨重新導向。時差取自最終回應的 `Date` 標頭。量測只讀取標頭，輸出寫到終端機。

- **時間差**為遠端時間減去本機請求起訖的中點時間，單位為毫秒。正值表示遠端較快，負值表示遠端較慢。
- **遠端時間**為收到標頭當下的估計時間，以本機時區顯示時、分、秒及三位毫秒。
- **RTT/2** 是請求往返時間的一半。`Date` 只有整秒精度，判讀小於一秒的差異時須考慮此限制。若由 CDN 或代理產生標頭，結果反映該設備的時鐘。

逐行模式將成功樣本寫入 stdout，單次逾時（1 秒）、連線失敗或缺少有效的 `Date` 時，原因寫入 stderr，之後繼續取樣。連線失敗時檢查網址及連線。缺少標頭時確認根路徑的 HEAD 回應包含 `Date`。

監看模式（`-m` 或 `--monitor`）每 10 ms 以本機現在時間加上最近 5 秒有效樣本的平均時差更新時鐘。主要數值為最近一次成功量測的時差、5 秒平均時差，以及該次成功量測的 RTT/2。下方以低亮度顯示最後更新時間、最小與最大時差及樣本數。若所有樣本都已過期，時鐘顯示 `--:--:--.---`，上次成功的數值轉為低亮度，畫面同時顯示最近的失敗原因。收到有效樣本後自動恢復。

畫面列出輸入的完整網址，並在啟動時對該網址送一次 `GET`，讀取 HTML 中的頁面標題。標題查詢與根路徑的 `HEAD` 取樣分開計時，查詢失敗時仍可持續監看。

四次量測中至少成功一次，或使用者按 Ctrl+C 結束時，結束碼為 0。四次全數失敗或執行錯誤為 1，命令列語法錯誤為 2。

## 以跳秒邊界校正

`clock-ping https://example.com/path --calibrate --count 5` 對指定路徑進行五輪校正，省略 `--count` 時執行一輪。準備階段以 1 秒間隔量測五次。每輪最多 20 秒，預設自動選擇步長，加上 `--min-step-ms 25` 可手動指定 1–100 ms。

以下為單輪輸出範例。

```text
準備中
校正中 count = 1（100 ms）
校正中 count = 1（25 ms）
結果 count = 1（25 ms）：+4.0 ms
```

結果是跨秒兩側中絕對值較小的那筆「網站減本機」時差，保留原本正負號。括號中的步長表示在哪個精度的掃描中觀察到跨越。若只在粗掃確認跨越，結果標示 100 ms。若該輪未取得結果，CLI 會列出輪次並繼續。準備失敗或任一輪未取得結果時，結束碼為 1。

當真實時差接近或超過半秒，絕對值較小的樣本可能落在前一秒，讀值因而與真實時差相差近一秒。[決策與數值範例](../docs/decision/0003-calibration-session.md)
